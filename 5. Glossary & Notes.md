# Glossary and notes

## Cloud Vs Onpremise

| Aspect | Cloud Database | On-Premises Database |
|---|---|---|
| **Location** | Hosted by a cloud provider (+) | Hosted on your own servers |
| **Cost** | Pay-as-you-go; lower initial cost (+) | Higher initial hardware investment |
| **Management** | Provider manages infrastructure (+) | Managed by internal IT team |
| **Scalability** | Easily scale resources up or down (+) | Scaling may require new hardware |
| **Security** | Shared responsibility with provider | Greater direct control over security (+) |
| **Control** | Limited control over underlying infrastructure | Full control over infrastructure (+) |
| **Accessibility** | Accessible over the internet or private connection (+) | Usually accessed through an internal network |
| **Backup & Recovery** | Managed backup options available (+) | Organization manages backups |
| **Availability** | Built-in redundancy options available (+) | Redundancy must be implemented internally |
| **Maintenance & Updates** | Often automated for managed services (+) | Handled by internal IT team |
| **Best For** | Flexible workloads and rapid deployment (+) | Strict control and specialized requirements (+) |

### Conclusion
> The best choice depends on the organization's requirements, security policies, and budget. <br>

> Cloud databases are generally better for scalability, quick deployment, and reduced infrastructure management. <br>
 On-premises databases are better when full control, customization, and direct infrastructure ownership are priorities. <br>


> _Sometimes if the provider's gone through outage, it can affect the entire organization, having offline backup can be neccessary_

### ETL
- It stands for Extract, Transform, Load : a way to move data from source systems into a place where it can be analyzed.
> Which could be database, data warehouse, data lake, etc.



### OLAP OLTP
Academic answer :  
- Online analytical processing (OLAP) : a system for performing multi-dimensional analysis at high speeds on large volumes of data.
- Online transactional processing (OLTP) : enables the real-time execution of large numbers of database transactions by large numbers of people, typically over the Internet.


> If OLTP is the cashier handling each sale accurately as it happens; <br>
Then OLAP is HQ looking across many sales to spot trends and make decisions. <br>


 **Examples** : Oracle for OLTP, PowerBi for OLAP





## Bidirectional
Bidirectional relationships in Power BI allow filters to propagate in both directions between related tables,<br>
which can be useful for syncing slicers and enhancing data analysis. <br>
However, they should be used cautiously as they can lead to performance issues and ambiguity in data models.



## Tables
 
### Dimension table
- Dimension tables describe business entities—the things you model. Entities can include products, people, places, and concepts including time itself.

- Tables that store descriptive information related to the data in the fact table.
- Each dimension table is connected to the fact table through foreign key relationships.
- Dimension tables provide context to the measures in the fact table.

> Examples of dimension tables include time, geography, product, and customer tables.

### Fact table
- Fact tables store observations or events, and can be sales orders, stock balances, exchange rates, temperatures, and more. 
- The central table contains the primary metrics or measures, often numerical data, that the business is interested in analyzing.
> Examples include sales, revenue, or quantity sold.

### Fact-less fact
- official term which means the fact table consists mostly of dimensional "foreign" keys without measures or numeric fields that can be aggregated.

### Measures vs Calculated Columns

| | Measure | Calculated Column |
|---|---|---|
| **When calculated** | At visual render time | At data refresh time |
| **Responds to slicers** | Yes | No — fixed at refresh |
| **Storage** | None — computed on demand | Stored in model — increases file size |
| **Use for** | Aggregations: SUM, COUNT, DIVIDE, AVERAGE | Row-level logic: categories, flags, combinations |
| **Icon in field pane** | Calculator | Table column |

```dax
-- Measure — goes in _Measures table
Total Revenue = SUM(fact_orders[revenue])

-- Calculated Column — goes in the source table
Price Tier =
IF(fact_orders[unit_price] > 1000, "Premium",
   IF(fact_orders[unit_price] > 500, "Mid", "Budget"))
```

**Common mistake:**
Creating a calculated column for something that needs to respond to filters. If the value should change when a slicer is used, it must be a measure — not a column.
